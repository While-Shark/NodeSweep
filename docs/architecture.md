# 架构与安全边界

## 组件

```
cmd/nodesweep      配置、运行模式、生命周期
internal/engine   Linux 指标、受限扫描、预览和执行
internal/hub      管理 API、节点认证和任务调度
internal/agent    主动 HTTPS 上报、后台任务执行
internal/store    SQLite 节点/规则/任务持久化
web/src           Vue + TypeScript 管理界面
```

按职责拆分，采集和清理引擎不依赖 HTTP。单机模式直接复用引擎，远程模式使用相同的任务与结果结构。

## 通信

Agent 每 5 秒 POST `/agent/poll`：指标、本地白名单、忙闲状态、待确认任务结果。Hub 返回至多一个任务。执行在 Agent 后台进行，心跳持续发送；结果发送失败会在下次轮询重试。

每个节点一个随机凭证。Hub 仅保存 SHA-256 摘要；节点不能访问管理员 API，也不能提交其他节点的任务结果。Agent 不跟随 HTTP 重定向，避免向新目标传递凭证。除 loopback 开发环境外仅接受 HTTPS。

任务先保存再下发。任务领取、超时和结果完成使用 SQLite 条件更新；重复完成只确认已有结果，不覆盖第一次完成数据。扫描摘要列表不把整棵目录树读入 Go 内存，定期压缩仅删除旧扫描载荷。退出时停止接收新任务，取消并等待本机任务及采集线程完成后再关闭数据库。

Hub 重启将未完成任务标记为 interrupted，不自动重放。网络断开或崩溃可能导致结果不确定：这是 at-most-once 下发，不提供分布式 exactly-once 承诺。对于不确定执行，重新扫描和预览，不能自动重试删除。

## 清理保护

1. Agent 本地配置白名单；HTTP 请求不能修改白名单。
2. 只允许绝对路径，按路径边界检查，拒绝符号链接路径。
3. Go `os.Root` 绑定目录边界，扫描不跨挂载点。
4. 归档文件类型、保留天数、模式、排除规则共同筛选。
5. 排除多硬链接、非普通文件和已打开文件；无法检查进程则拒绝。
6. 预览保存 inode、设备号、大小、修改时间，十分钟有效，一次消费。
7. 删除前再次检查。通过绑定目录把文件原子移入同目录私有临时子目录，重新核对身份和打开状态，再删除。
8. 身份不符时不删除，通过 `RENAME_NOREPLACE` 恢复；原位置已有新文件或恢复失败，则保留临时文件并在结果中给出路径。

正常归档清理不调用 Shell，不接受任意命令，不递归删除目录。执行中断或进程崩溃可能留下 `.nodesweep-*/item`，需要按任务记录人工检查；不会自动递归清理这些目录。预览默认排除这些内部目录。

## 信任边界和限制

- 支持只读／操作员／管理员独立凭据。权限作用于整个 Hub，管理员可配置多个身份；没有逐节点或多租户隔离。
- 访问令牌在配置中明文保存（0600），仅驻留浏览器内存；刷新后重新登录。外部访问必须通过 HTTPS。
- 节点 root 用户能篡改上报数据或本机文件，不把已被攻陷的 Agent 当成可信监控数据源。
- 文件仍可能在最后检查后被进程打开/写入；只对不再使用的归档启用规则。没有通用机制能原子锁住所有第三方应用的文件打开操作。
- 文件占用检查要求完整可见的宿主机进程信息；容器内看不到宿主机进程时，不适合作为清理 Agent。
- 临时隔离与同目录文件系统操作保证的是身份复核，不是备份或回收站。
- 扫描单线程、按需触发、有条目/时间上限。深度目录和海量小文件仍可能造成磁盘 I/O，应选择合适目录和时段。
- 指标历史曲线、计划任务、用户权限分级尚未实现。
